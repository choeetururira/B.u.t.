# 03. 데이터 저장 구조

모든 값은 시트에 **텍스트 서식(@)** 으로 저장됩니다(PIN `0042` 의 앞자리 0, 학생 번호 `07` 이 숫자로 바뀌지 않도록). 열 정의는 `src/shared/core.js` 의 `SCHEMA` 하나에서 관리합니다.

## 스프레드시트 `B.U.T. TOKYO 2026 – 기록 데이터 (비공개)`

### `Students` — 학생 명단

| 열 | 설명 |
|---|---|
| studentId | 학생 번호 (영문·숫자 12자 이내, 예: `07`) |
| pin | 4~6자리 숫자 |
| name | 실명(선택, 관리자 화면에만 표시) |
| displayName | 결과물에 쓰는 이름 (기본 `STUDENT 07`) |
| group | 모둠(선택) |
| exhibitConsent | 사진 전시 동의 `TRUE/FALSE` |
| teacherComment | 성장 기록지 "선생님의 한마디" |
| active | 사용 여부 |
| createdAt | 생성 시각(ISO) |

### `Submissions` — 제출 기록 (학생 × 날짜, 재제출 이력 포함)

| 열 | 설명 |
|---|---|
| submissionId | 접수 번호 (`S…`) |
| clientSubmissionId | 휴대폰이 만든 제출 ID — 같은 값이 다시 오면 중복으로 처리 |
| studentId, day | 학생 번호, DAY(1~4) |
| revision | 회차 (재제출마다 +1) |
| status | `current`(현재) / `superseded`(이전 회차 보관) |
| submittedAt | 제출 시각 |
| reflection, essay, oneLine | 학생 원문 (성찰 답변·소감문·한 줄) |
| photoIds | 사진 ID 목록(JSON) |
| editedReflection, editedEssay, editedOneLine | 교사 수정본 (비어 있으면 원문 사용) |
| featuredPhotoId | 포스터 카드에 쓸 사진 |
| topics | 교사가 지정한 주제(JSON, 비어 있으면 자동 분류) |
| reviewStatus | `pending` 검토 대기 / `approved` 승인 / `hold` 보류(결과물 제외) |
| teacherNote | 교사 메모(학생 비공개) |
| editedAt, userAgent | 교사 수정 시각, 제출 기기 정보 |

> 학생별·날짜별 현재 기록만 보려면 시트에서 `status = current` 로 필터링하세요.

### `Photos` — 사진

| 열 | 설명 |
|---|---|
| photoId | 사진 ID (`P…`) |
| studentId, day | 소유 학생, 날짜 |
| clientUploadId | 업로드 재시도 시 중복 저장 방지용 ID |
| originalFileId | Drive 원본 파일 ID (휴대폰 원본 그대로) |
| displayFileId | Drive 출력용 사본 ID (긴 변 2000px JPEG) |
| mime, originalName, bytes | 원본 형식·파일명·크기 |
| width, height | 출력용 사본 크기(px) |
| caption, mission | 학생이 쓴 사진 설명, 관련 미션(1/2) |
| exhibit | 전시 후보(팜플렛·주제 포스터 우선 사용) |
| uploadedAt, submissionId | 업로드 시각, 연결된 제출 |

### `Settings` — 설정 (key / value(JSON))

| key | 의미 |
|---|---|
| `openMode` | `all`(모든 DAY 제출 가능) / `byDate`(도쿄 날짜가 되어야 열림) |
| `locks` | `{"1": true}` 처럼 DAY별 마감 |
| `heroes` | `{"1": "P…"}` DAY별 포스터 대표 사진 |

### `Log` — 감사 기록

로그인, 로그인 실패, 제출, 재제출, 교사 편집, 설정 변경, 결과물 저장, 삭제, 서버 오류가 시각과 함께 남습니다.

## Drive 폴더 `B.U.T. TOKYO 2026 (비공개 · 학생 사진과 결과물)`

```
B.U.T. TOKYO 2026 (비공개 · 학생 사진과 결과물)/
├── B.U.T. TOKYO 2026 – 기록 데이터 (비공개)      ← 스프레드시트
├── photos/
│   ├── original/DAY1 … DAY4/   07_D1_P3f2…_orig.jpg     ← 휴대폰 원본
│   └── display/DAY1 … DAY4/    07_D1_P3f2…_print.jpg    ← 출력용 사본
└── outputs/                     DAY01_A1_포스터.pptx …   ← 관리자 [Drive 저장]
```

파일명이 `학생번호_D날짜_사진ID` 로 시작하므로 Drive에서도 학생별·날짜별로 정렬됩니다.

## 스크립트 속성 (Apps Script → 프로젝트 설정)

| 키 | 내용 |
|---|---|
| `SPREADSHEET_ID`, `ROOT_FOLDER_ID`, `FOLDER:*` | 시트·폴더 ID |
| `TOKEN_SECRET` | 토큰 서명용 비밀키 (삭제하면 전원 로그아웃) |
| `ADMIN_HASH` | 관리자 비밀번호 해시 |

## API (google.script.run.api(action, payload) / POST JSON)

| action | 권한 | 설명 |
|---|---|---|
| `studentLogin` | — | 학생 번호+PIN → 토큰, 날짜별 상태 |
| `myStatus`, `mySubmission`, `myPhoto` | 학생 | 내 상태 / 내 기록 / 내 사진 |
| `uploadPhoto` | 학생 | 사진 1장(원본+출력용 사본) |
| `submit` | 학생 | 기록 제출 (`created` / `duplicate` / `exists` / `updated`) |
| `adminLogin` | — | 비밀번호 → 관리자 토큰 |
| `adminOverview`, `adminSubmissions`, `adminHistory` | 관리자 | 현황, 검토 목록, 회차 이력 |
| `adminUpdateSubmission`, `adminUpdatePhoto` | 관리자 | 편집·검토 상태·주제·카드 사진 / 전시 후보 |
| `adminPhotos` | 관리자 | 사진 데이터(최대 12장/회) |
| `adminStudents`, `adminUpsertStudent`, `adminGenerateStudents` | 관리자 | 학생 관리 |
| `adminSettings` | 관리자 | 마감·개방 방식·대표 사진 |
| `adminDataset` | 관리자 | 결과물용 데이터(실명 제외) |
| `adminSaveOutput` | 관리자 | 결과물 파일을 Drive `outputs` 에 저장 |
| `adminPurge` | 관리자 | 제출물·사진 전체 삭제 (`confirm: "DELETE"`) |

응답 형식: `{ ok: true, data }` 또는 `{ ok: false, error: { code, message, extra } }`.
